# SEP-5: Evidence Batching

Status: draft · Editor: SigmaUno project maintainers

## Purpose

Aggregate commitments and provide deterministic inclusion witnesses.

## Design requirements

Candidate RFC 6962-style construction uses distinct leaf/node prefixes, ordered leaves, and explicit leaf index and tree size. Preserve exact manifest bytes and bind root, algorithm, count, and version. Public IDs must be non-identifying and generated by the system.

## Decisions required before implementation stability

Define exact leaf preimage, empty-tree behavior, odd-sized tree construction, proof serialization, and manifest-to-provider binding. Publish vectors for size 1 and non-power-of-two trees, reordered leaves, truncated/extra paths, and wrong index/count. A root string alone does not authenticate the rest of a manifest.

## Acceptance

Publish precise byte-level rules, independent positive and negative test vectors, compatibility behavior, and security considerations. Review before marking this draft stable.
