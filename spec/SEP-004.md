# SEP-4: Event Chains

Status: draft · Editor: SigmaUno project maintainers

## Purpose

Bind ordered lifecycle assertions to object versions and predecessor evidence.

## Design requirements

Conceptual event fields: domain, version, object commitment, event type, payload digest, actor assertion/commitment, claimed timestamp, sequence, and previous event hash. Define genesis and head semantics. Events may include creation, OCR, metadata updates, signing, classification, archival, retention expiry, and renewal.

## Decisions required before implementation stability

Specify concurrent append control, forks, missing predecessors, externally authenticated heads, and source versus observation time. Hidden suffixes and never-recorded events cannot be ruled out by hash linking alone.

## Acceptance

Publish precise byte-level rules, independent positive and negative test vectors, compatibility behavior, and security considerations. Review before marking this draft stable.
