# SEP-2: Document Commitments

Status: draft · Editor: SigmaUno project maintainers

## Purpose

Bind exact object bytes and optional metadata to a private randomized commitment.

## Design requirements

Conceptually: H(domain || version || document_digest || metadata_state || nonce). Use a cryptographically random 32-byte nonce per commitment. Include algorithm identifiers in the authenticated structure; distinguish source object ID, version, and representation from digest identity. Publish no raw document digest or nonce.

## Decisions required before implementation stability

Specify unambiguous length framing or canonical structured encoding, absent-metadata encoding, domain bytes, algorithm registry, and nonce lifecycle. Never implement ambiguous string concatenation. Supply vectors for changed byte, nonce, algorithm, and representation.

## Acceptance

Publish precise byte-level rules, independent positive and negative test vectors, compatibility behavior, and security considerations. Review before marking this draft stable.

## Experimental profile 1 — proposed for review

The [commitment primitive](../pkg/proof/commitment/README.md) implements this exact profile as a development experiment. It is not a stable interoperable release. Reviewer acceptance and the remaining envelope/manifest decisions in #2/#4 are required before publishing production evidence. Future incompatible changes require a new version; do not reinterpret profile 1 bytes in place.

Choose fixed-width binary framing for this preimage. It avoids JSON number, Unicode, key-order and duplicate-key ambiguities. This decision does not select the outer envelope encoding. Compute `SHA-256(preimage)` over exactly 90 bytes:

| Offset | Length | Field | Accepted value |
| --- | --- | --- | --- |
| 0 | 22 | Domain | ASCII `sigmaproof:commitment` followed by byte `00` |
| 22 | 1 | Encoding version | `01` |
| 23 | 1 | Digest/commitment algorithm | `01` = SHA-256 for both operations |
| 24 | 1 | Representation | `01` = original, `02` = derived |
| 25 | 1 | Metadata state | `00` = absent; all other values rejected |
| 26 | 32 | Document digest | SHA-256 of exact document bytes |
| 58 | 32 | Private nonce | Fresh 32-byte CSPRNG output for new evidence |

Integers here are single unsigned bytes. Digests and nonce are raw bytes, not hexadecimal text. No lengths, terminators, padding or trailing fields are added. The one terminating zero in the domain is mandatory. Empty documents are permitted; their digest is SHA-256 of zero bytes. Byte limits are caller-selected operational policy and are not encoded into the commitment.

Original/derived labels are producer assertions: this encoding distinguishes representations but does not authenticate that the source actually supplied one or the other. A derived representation includes OCR/archive variants. No Unicode normalization, PDF rewriting or metadata extraction occurs before hashing. Source instance/object/version IDs remain in private ingestion records; a document digest is not a unique source identity. Repeated bytes with independently generated nonces intentionally yield different commitments.

Metadata is absent in this MVP profile. There is no metadata digest field; callers cannot claim verified metadata, and nonzero metadata states are unsupported. Unknown algorithm/version/representation values are rejected without fallback. Adding metadata or new representation semantics requires a reviewed versioned extension.

The producer generates one nonce per new ingestion and persists the witness transactionally with its idempotency record. Retries and crash recovery reuse that witness. Do not generate a new witness on every retry. Import/verification can accept any 32-byte nonce (including synthetic test values); its entropy cannot be verified after the fact.

Only the resulting opaque 32-byte commitment may enter the public batch as an entry. The digest, nonce, representation and preimage stay in the customer's private proof material. Apply the SEP-5 leaf prefix to the commitment bytes once. Never anchor the private preimage or a raw document digest. The outer manifest still needs to bind the tree algorithm, size, version and root; the primitive itself provides no publication or provenance authentication.

### Reproducible vectors

[Profile fixtures](../pkg/proof/commitment/testdata/sep2-draft.json) include exact document, digest, nonce, preimage and commitment hex for empty, text and binary documents and single-input variations. These values are entirely synthetic. Generate them with `python3 scripts/generate_commitment_vectors.py`; production must not reuse fixture nonces. Go tests reproduce the fixed-width Python results and reject changes to every semantic field. This is a cross-language check by this project, not independent external review.
