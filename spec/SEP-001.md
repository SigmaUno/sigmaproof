# SEP-1: Evidence Envelope

Status: draft · Editor: SigmaUno project maintainers

## Purpose

Define portable package serialization, content addressing, resource bounds, extension handling, and immutable revisions.

## Design requirements

Preserve protocol/algorithm IDs, document representation and digests, private nonce, metadata presence/digest, evidence links, batch manifest and path, provider witnesses, trust evidence, and complete policy definitions where used. References must resolve inside the exported bundle for required material. External retrieval is optional enrichment.

## Decisions required before implementation stability

Choose canonical JSON (evaluate RFC 8785) or deterministic binary encoding, byte framing, attachment layout, signature scope, size/depth limits, and unknown-field behavior. Reject duplicate keys and unsupported critical versions. A schema validates structure, not cryptographic authenticity.

## Acceptance

Publish precise byte-level rules, independent positive and negative test vectors, compatibility behavior, and security considerations. Review before marking this draft stable.
