# SEP-6: Anchor Receipts

Status: draft · Editor: SigmaUno project maintainers

## Purpose

Represent provider-specific portable evidence and its authentication prerequisites.

## Design requirements

Receipts identify provider, proof version, network, committed input, submission state, inclusion witness, relevant state, and required trust context. Pending receipts never count as authenticated evidence. Celestia must preserve the complete manifest-to-authenticated-header path; OpenTimestamps must preserve completed Bitcoin attestations rather than only pending calendar promises.

## Decisions required before implementation stability

Freeze no Celestia witness until a pinned-release feasibility experiment passes. Define asynchronous capture and finality, checkpoint provenance, independent verification, unsupported providers, and evidence of trust-service qualification separately from public inclusion.

## Acceptance

Publish precise byte-level rules, independent positive and negative test vectors, compatibility behavior, and security considerations. Review before marking this draft stable.
