# SEP-7: Evidence Policies

Status: draft · Editor: SigmaUno project maintainers

## Purpose

Evaluate explicit evidence requirements independently from basic cryptographic validity.

## Design requirements

Preserve policy ID, version, canonical definition, digest, and signature/trust context where required. Express allowed algorithms, mandatory evidence, anchor types and independence, thresholds, timestamps, retention, and renewal. Verifier-selected policy may be stricter than package policy; report both identities.

## Decisions required before implementation stability

Define satisfied/not_satisfied/indeterminate logic, mandatory unsupported assertions, historical versus current trust, provider independence, signed-policy authenticity, and renewal enforcement. Never infer legal compliance from an illustrative profile.

## Acceptance

Publish precise byte-level rules, independent positive and negative test vectors, compatibility behavior, and security considerations. Review before marking this draft stable.
