# Governance

SigmaUno stewards the initial project. Repository administrators manage access and releases; contributors propose changes through issues and pull requests. Maintainer appointments and changes should be recorded publicly where appropriate.

Protocol decisions require a written rationale and recorded review. Breaking changes require explicit version changes and migration/verification guidance. Draft SEPs are not stable interoperability promises. Keep specifications implementable independently of SigmaUno services.

Before the first implementation release, define release signing, supported versions, vulnerability handling ownership, and compatibility policy. Do not tag a foundation-only repository as an MVP.
